# Архитектура

## Слои

```
┌──────────────────────────────────────────────────────────┐
│  Game/          геймплей: мир, игрок, монстры, оружие     │  ← перенос 1:1 из C
│                 предметы, двери, эффекты, меню, сейвы     │
├──────────────────────────────────────────────────────────┤
│  Net/           lockstep-сессия, протокол, мост к игре     │  ← новый код
│  Ui/            оверлей по F2 (GDI)                        │
├──────────────────────────────────────────────────────────┤
│  Engine/        платформа: WAD, VGA, палитра, ввод, звук   │  ← переписан под C#
│  Audio/         микшер, waveOut, XM-плеер                  │
├──────────────────────────────────────────────────────────┤
│  Win32/         user32 + gdi32: окно, DIB, ввод, оверлей   │  ← нативно
└──────────────────────────────────────────────────────────┘
```

Граница переноса проходит там, где в оригинале были `vga.h`, `files.h`,
`sound.h` и `keyb.h`. Всё, что выше, — построчный перенос C-кода; всё, что ниже,
— новый код под платформу.

## Никаких сторонних библиотек

Это осознанное решение, а не ограничение. Каждая часть платформы сделана на том,
что уже есть в Windows с незапамятных времён:

| Задача | Решение | Почему не библиотека |
|---|---|---|
| окно | `user32`: `CreateWindowEx`, свой `WndProc` | WinForms тянет за собой большую часть .NET |
| вывод кадра | `gdi32`: DIB-секция + `StretchBlt` | SDL/OpenGL — лишний DLL рядом с exe |
| ввод | сообщения окна, `keybd_event`-совместимо | SDL-ввод — ещё одна зависимость |
| звук | `winmm`: `waveOut` + свой микшер | XAudio2 требует SDK, SDL_mixer — DLL |
| музыка | свой плеер FastTracker 2 | mikmod/libopenmpt — DLL и лицензии |
| сеть | `System.Net.Sockets` (часть BCL) | — |
| лаунчер | WinForms | это GUI-инструмент, а не игра |

Итог: `dptdoom2d.exe` (342 КБ) + `Data/` — и ничего больше. Работает на
Windows XP SP3 и на Windows 11.

## Рендер остался программным

Doom2D рисует в 8-битный палитровый фреймбуфер 320×200. На индексах палитры
завязано всё:

| Что | Как в оригинале |
|---|---|
| затенение по расстоянию и урону | `clrmap[12][256]` — замена индекса по таблице |
| дым | `mixmap[256][256]` — смешение двух индексов |
| огонь | `flametab[16]` |
| цвет игрока | индексы `0x70..0x7F` перекрашиваются на лету |
| вода | индекс не рисуется, а тонируется colormap'ом поверх фона |

Поэтому:

```
Vga.Buffer (byte[], 320×200)  ──палитра──▶  uint[] BGRA  ──CopyMemory──▶  DIB
        ▲                                                                  │
        │                                                                  ▼
   Vga.Spr / Vga.Clr / Vga.Pic                              StretchBlt (COLORONCOLOR)
   (построчный перенос из vga.c)                            ×1..×6, целочисленно
```

Один блит на кадр. Оригинал удваивал пиксели в окно 640×400 — здесь то же самое
делает `StretchBlt` с `COLORONCOLOR` (это nearest-neighbour), поэтому при любом
масштабе пиксели остаются квадратными.

Побочный плюс: `--simulate` умеет отрисовать кадр без GPU и записать BMP, чем и
пользуются тесты и генератор картинок для документации.

## Что пришлось решать по-другому

**Указатели → объекты.** В C `void *p` — это одновременно «залоченный ресурс» и
«указатель на `vgaimg`», а `((int*)p)[-1]` даёт номер ресурса. В C# это
`Res.Locked` (номер + байты + ленивый `VgaImage`), поэтому `Z_sound(p, v)` и
`Vga.Spr(x, y, img)` читаются как в оригинале.

**`keys[SDLK_*]`.** Игровая логика в C индексирует массив клавиш SDL-keysym'ами.
Вместо размазывания Win32-кодов по геймплею `Kbd` один раз за тик переводит
виртуальные клавиши в keysym'ы. В результате `player.c` и `menu.c` переносятся
почти без изменений — и то же самое позволяет сети подменить клавиатуру
вводом второго игрока.

**Сохранения.** Оригинал пишет сырые структуры `#pragma pack(1)`. Здесь те же
поля пишутся по одному через `BinWriter`/`BinReader` — формат остаётся
байт-совместимым (`ver=3`), но без `unsafe` и маршаллинга.

**Анимации монстров.** В C `char *ap` — указатель на строку кадров; в сейв он
попадает как адрес. Здесь анимация опознаётся по содержимому и восстанавливается
по индексу.

**Автоповтор клавиш.** Windows присылает `WM_KEYDOWN` много раз, пока клавиша
нажата. Игра должна видеть одно нажатие: бит 30 в `lParam` — то, что отличает
повтор от первого нажатия.

**Детерминизм.** `System.Random` не гарантирует одинаковую
последовательность между рантаймами, поэтому игровой ГПСЧ — свой LCG с
константами MSVC `rand()`. Без этого lockstep невозможен.

## Поток одного тика

```
Kbd.Update()            сообщения окна → keys[] + нажатия за тик
Overlay.HandleKey()     F2 и настройки; если вкладка активна — ввод не идёт в игру
Menu.Act()              меню/читы (в сети недоступно: пауза = десинк)
World.Act()             анимация стен
Items / Switches        подбор, двери
Player.Act()            движение, стрельба, смена оружия
Monsters.Act()          AI, стрельба, смерть
Bmap                    перестройка блочной карты
Weapons / Dots / Smoke / Fx
Player.Damage()         применение накопленного урона
```

20 тиков в секунду (`DELAY 50`) — ровно как в DOS-версии, поэтому тайминги
анимаций, скоростей и звуков совпадают.
