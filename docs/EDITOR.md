# Редактор карт

`dptdoom2d-editor.exe` — отдельная программа, но **не Windows-приложение**: это
VGA-программа с собственным окном, как оригинальный `EDITOR.EXE` 1996 года.
Кадр — тот же 320×200 палитровый буфер, что у игры, карта рисуется настоящими
текстурами и спрайтами из WAD.

## Почему так, а не WinForms

В DOS редактор был игрой без игры: свой экран, своя палитра, свои панели, мышь и
клавиатура напрямую. WinForms здесь был бы чужим слоем — и по правилам проекта
(`AGENTS.md`) разрешён только лаунчеру.

Поэтому редактор работает на том же нативном слое, что и игра:
`Win32Window` + `Vga` + `Palette`. **Весь интерфейс**, включая текст, рисуется в
8-битный буфер; второго прохода в разрешении окна нет. Окно растягивает одну и ту
же картинку — ровно так же, как у игры, поэтому `-scale` и `-stretch` означают
здесь то же самое, и при 1× и при 6× редактор выглядит одинаково, только крупнее.

Оригинальные бинарники для сверки лежат в `refs/D2D_Also/editor-original/`
(`EDITOR-130.EXE`, `EDITOR-140.EXE`) — они не в репозитории, `refs/` в
`.gitignore`.

## Как сверялось с оригиналом

Оригинальный `EDITOR.EXE` был снят в DOSBox, скриншоты лежат в `docs/images`:

| Файл | Что на нём |
|---|---|
| `editor-original-things.png` | вкладка «Вещи, монстры и т.п.» |
| `editor-original-wall.png` | вкладка «Фон» |
| `editor-original-types.png` | вкладка «Стены, двери и т.п.» |
| `editor-original-switches.png` | вкладка «Кнопки» |

Сравнение шло численно, а не на глаз: `--shot` рисует кадр 320×200 без окна и без
масштабирования, эталон уменьшается до тех же 320×200, после чего считается
разница по пикселям. Так и нашлись три вещи, которые «на глаз» выглядели нормой:

- **Гамма.** В `EDITOR.CFG` оригинала стоит `gamma=1`, и `edit()` вызывает
  `setgamma(gamma)` при старте. Редактор порта рисовал при 0 — вся серая шкала
  была темнее ровно на одну ступень (панель 96 вместо 117). Теперь `-gamma`
  работает и по умолчанию равен 1, как в оригинале.
- **Шрифт.** Оригинал **не** брал шрифт из WAD. Его GUI-библиотека несла свой
  `SMALLFNT.VGA` — 3×5 на шаг 4 пикселя. Шрифт `STCFN*` из WAD (8×7, с
  кириллицей только заглавными) — это шрифт статус-строки игры, и текст им
  выглядел заметно крупнее оригинала.
- **Серая шкала.** `gray[i] = getbestcolor(i*4,i*4,i*4)` считается из
  загруженного `PLAYPAL`, а не задаётся индексами: редактор обязан работать с
  тремя разными WAD.

## Запуск

`Editor.bat` из дистрибутива или `dptdoom2d-editor.exe` напрямую:

```powershell
dptdoom2d-editor.exe
dptdoom2d-editor.exe MAP07
dptdoom2d-editor.exe Data\Maps\mypack.wad
dptdoom2d-editor.exe -scale 2 -stretch smooth -gamma 1
```

Без аргументов открывается `MAP01`.

| Ключ | Значение |
|---|---|
| `-scale N` | масштаб окна 1..6, `0` — подогнать под экран |
| `-stretch nearest\|pixel\|smooth` | как растягивать кадр; так же, как у игры |
| `-gamma 0..4` | яркость; по умолчанию 1, как в `EDITOR.CFG` |
| `-fullscr` / `-window` | полноэкранный режим |

## Экран

Раскладка скопирована из `edit()` в `EDIT.CPP` по координатам, а не на глаз:

```
┌──────────────────────────────┬──┬─────────────────┐
│  карта 200×98                │▓▓│ ☑ икон ☑ икон   │  чекбоксы слоёв (215, 10..70)
│                              │▓▓│ ☑ икон ☑ икон   │  иконки (240, 14..74)
├──────────────────────────────┴──┤ ☑ икон          │
│ ◄═══════════ скролл ═══════════►│                 │  hscroll (0,100,200,10)
├──────────────────┬──────────────┤  [система] [?]  │  b1 (305,2)  b5 (308,15)
│ ▓ вкладки        │  ЗАГОЛОВОК   │  [загрузить]    │  b2 (270,10)
│ ▓ ▓ ▓ ▓ ▓        │  содержимое  │  [записать]     │  b3 (270,40)
│ ▓ (20 px)        │              │  [ Музыка ]     │  b4 (265,70)
└──────────────────┴──────────────┴─────────────────┘
                                   ┌───────────────┐
                                   │  миникарта    │  mapwin (213,93,104,104)
                                   └───────────────┘
```

| Элемент | Координаты в оригинале |
|---|---|
| карта | `view(0,0,250,110)`, вид `200×98` |
| полосы прокрутки | `hscroll(0,100,200,10)`, `vscroll(200,0,10,100)` |
| чекбоксы слоёв | `chkbox(215, i*15+10, 10, 9)`, `i = 0..4` |
| иконки слоёв | `V_spr(240, i*15+14)` |
| миникарта | `mapwin(213,93,104,104)` |
| вкладки | `vcontbox(0,110,210,90)`, полоса 20 px |
| система / загрузка / запись / музыка / справка | `b1(305,2,13,10)`, `b2(270,10,16,15)`, `b3(270,40,16,15)`, `b4(265,70,36,15)`, `b5(308,15,6,7)` |

Камера — это `w_x`/`w_y` оригинала: **центр** вида в пикселях карты, а не его
угол. Через эти две величины идут и рисование, и миникарта, и полосы прокрутки,
поэтому они не могут разойтись.

## Управление

| Что | Чем |
|---|---|
| нарисовать прямоугольник | левая кнопка, протянуть, отпустить |
| стереть прямоугольник | правая кнопка, протянуть, отпустить |
| поставить / убрать предмет | правая кнопка по пустому месту / по предмету |
| перетащить предмет | левая кнопка на предмете |
| поставить кнопку | левая + правая одновременно |
| задать точку действия | правая кнопка при выбранной кнопке |
| перейти по карте | клик по миникарте |
| прокрутка | колесо или стрелки |
| вкладка | `1`..`5`, `Tab` или клик по полосе |
| показать/скрыть слои | `B` / `F` / `T` или чекбокс |
| отменить | `Ctrl+Z` (40 шагов, один шаг = один мазок) |
| новая карта | `Ctrl+N` |
| записать / загрузить | `F2` / `F3`, либо `Ctrl+S` / `Ctrl+O` |
| запустить игру на карте | `F5` |
| справка | `F1` |
| выход | `Esc` (спросит про несохранённое) |

Поведение мыши повторяет `view::mouse` из `EDIT.CPP`, включая мелочи: клик по
строке состояния вида (`y==0` или `y>=99`) не рисует, а «кнопка» ставится именно
двумя кнопками сразу — так написано в справке оригинала.

## Слои

| Слой | Что это | Блок в файле |
|---|---|---|
| **Фон** | стены за игроком | `MB_BACK` |
| **Стены, двери и т.п.** | тип клетки: стена, дверь, вода, лава, лифт | `MB_WTYPE` |
| **Передний план** | стены перед игроком | `MB_FRONT` |
| **Вещи, монстры** | предметы, монстры, точки старта | `MB_THING` |
| **Кнопки** | триггеры и их цели | `MB_SWITCH` |

Слой типов игра не рисует вообще — это карта столкновений. Редактор показывает её
блоками 4×4 пикселя по центру клетки, цветами из `tctab` (`MISCA.ASM`): текстура
под ними остаётся читаемой.

Миникарта — тоже слой типов (`Z_drawmap` прогоняет `fld` через `tctab`), а не
стены: по ней видно, где по уровню можно пройти, чего слой стен не показывает.

## Сохранение

`F2` пишет **PWAD с одной лампой** в `Data/Maps`. Игра грузит его как обычно:

```powershell
dptdoom2d.exe -file Data\Maps\mylevel.wad -warp 1
```

Формат — родной Doom2D, блоки в порядке DOS-редактора (`FILES.C: F_savemap`):
музыка, небо, стены, три слоя, предметы, триггеры, конец. Слои сжимаются тем же
RLE, что в оригинале (`pack()`: серия из пяти и более одинаковых байт).

## Проверки

Формат держится не на честном слове — в `build.ps1` несколько прогонов:

| Команда | Что проверяет |
|---|---|
| `dptdoom2d.exe --mapcheck` | 19 карт игры и 246 карт из 166 паков: чтение → запись → чтение **байт в байт** |
| `dptdoom2d.exe --mapsave MAP01 out.wad` | записанная карта грузится и даёт **побитово тот же кадр** |
| `dptdoom2d-editor.exe --save MAP02 out.wad` | то же **через код сохранения редактора**, а не через отдельный путь |
| `dptdoom2d-editor.exe --undocheck` | отмена возвращает карту байт в байт |
| `dptdoom2d-editor.exe --newmap out.wad` | новая карта грузится и играется |
| `dptdoom2d-editor.exe --render MAP01 out.bmp` | вся карта без окна: текстуры, спрайты, слой типов |
| `dptdoom2d-editor.exe --shot MAP01 out.bmp 3` | **кадр редактора** 320×200 без окна — для сверки с эталоном |

`--shot` — то, чем сверялись скриншоты DOSBox. Он рисует ровно тот кадр, который
показывает окно, но без заголовка и без масштабирования, поэтому разницу видно в
цифрах, а не «вроде похоже».

## Чего пока нет

- **Диалоги выбора файла** — вместо `choose_file` из оригинала однострочный ввод
  имени.
- **Полноценный список текстур с «Добавить»** — кнопка есть, но имя берётся из
  WAD, а не вводится.
- **Вкладка «Код»** — редактор `actors.txt` из [ROADMAP.md](ROADMAP.md).
- **Мышь в игре и меню** — отдельный пункт плана; редактор уже её использует.

## Сделано сверх оригинала

- **Отмена** (`Ctrl+Z`): в DOS-редакторе её не было вообще, и неверно
  поставленная стена стоила вечера. Здесь стек на 40 шагов, шаг — один мазок, а
  не одна клетка. Проверка `--undocheck` требует, чтобы отмена вернула карту
  **байт в байт**.
- **Новая карта** (`Ctrl+N`): пол с рамкой и точка старта. Стена рамки берётся из
  реального уровня этого WAD — имя, которого нет, это `Fatal` при загрузке.
- **`F5`** — играть на текущей карте, не выходя из редактора.
- **`--shot`** — кадр без окна, для сверки и для документации.

## Для агентов

- Карта — `Game/MapFile.cs`. Формат менять нельзя: `--mapcheck` сравнит и упадёт.
  Новое поле — только новый блок (`MB_*`), старые читаются как раньше.
- Редактор — инструмент, но WinForms здесь **нельзя**: только `Win32Window` и
  `Vga`, как у игры. Иначе он перестанет быть тем, чем был оригинал.
- **Никакого GDI.** `EditorUi.cs` удалён: интерфейс целиком в буфере, иначе при
  растяжении окна текст и панели разъезжаются.
- Виджеты — `EditorSkin.cs`, порт `GUI.CPP`. Новый элемент интерфейса берётся
  оттуда же, а не рисуется «похоже»: цвета — только `EditorSkin.G(i)`, то есть
  `gray[i]`.
- Текст — `EditorFont.cs`, шрифт `SMALLFNT.VGA` из `EditorAssets.cs`. Это **не**
  шрифт WAD. Кириллица в CP866, регистр не складывается.
- Иконки — `EDITOR.VGA` из `EditorAssets.cs`, вкомпилированы: собранный
  дистрибутив не должен зависеть от `refs/`.
- Мышь — `Win32Window.MouseToFrame`; она уже учитывает режим растяжения, и
  второй такой расчёт заводить не нужно.
- Меняешь картинку — сними `--shot` и сравни с `docs/images/editor-original-*.png`.
  Расхождение в один индекс палитры видно в числах и незаметно на глаз.
