# Язык акторов (actors.txt)

Данные монстров — это данные, а не код. Файл `actors.txt` описывает размеры,
спрайты, звуки и последовательности кадров; движок читает его при запуске.
Встроенные двадцать типов описаны **тем же языком** внутри игры (`Game/Actors.cs`),
поэтому парсер проверяется на каждом запуске, а мод переопределяет любой тип по
имени.

Формат — дальний родственник DECORATE из ZDoom: та же идея (имя, свойства,
метки состояний), но без того, что 2D-игре 1996 года не нужно. Выражений,
скриптов и действий здесь нет: ИИ остаётся в `monster.c`, а определение задаёт
только то, что этот ИИ читает.

```
actor Imp2
{
    radius 10   height 28   health 40   painchance 15
    revisit 3   jump 10     slop 30     minpain 0
    sprite TROO   frames 42
    sound see   BGACT
    sound death DSIMPDTH
    states
    {
    spawn:  AAABBB
    see:    AABBCCDD
    death:  IIIJJJKKKLLL
    }
}
```

## Куда класть файл

| Место | Когда |
|---|---|
| `actors.txt` рядом с exe | локальная правка, переживает переустановку модов |
| `Data/actors.txt` | то же, но в папке данных |
| PK3/ZIP, файл `actors.txt` | мод: подключается через `-file` или лаунчер |
| WAD, лампа `ACTORDEF` | мод одним WAD'ом |

Читаются все источники по порядку, **последний побеждает** — мод, загруженный
через `-file`, перекрывает пак карт. Переопределение действует по полям: мод,
который меняет только `health`, оставляет остальные свойства встроенными.

## Грамматика

```
file      := actor*
actor     := "actor" name "{" member* "}"
member    := property | sound | states
property  := key value
sound     := "sound" slot lump
states    := "states" "{" (label ":" frames)+ "}"
label     := "spawn" | "see" | "pain" | "wait" | "melee"
           | "death" | "slop" | "dead" | "mess" | "missile"
frames    := (frameLetters [duration] | "none")*
```

- Регистр не важен: `Actor`, `ACTOR` и `actor` — одно и то же.
- Комментарии: `//` до конца строки, `/* ... */`, и `;` — как в `default.cfg`.
- Строки в кавычках: `"..."` или `'...'`, экранирование `\"`, `\'`, `\\`.
- Числа: десятичные и шестнадцатеричные (`0xD0`).
- `none` вместо кадров — состояние намеренно пустое (монстр остаётся в текущем
  кадре).

## Свойства

| Свойство | Диапазон | По умолчанию | Что |
|---|---|---|---|
| `radius` | 0..512 | — | радиус коллизии в пикселях |
| `height` | 0..512 | — | высота |
| `health` | 0..9999 | — | жизни |
| `painchance` | 0..9999 | — | порог боли (сколько урона до вздрагивания) |
| `revisit` | 0..64 | — | скорость ходьбы |
| `jump` | 0..64 | — | сила прыжка |
| `slop` | 0..999 | — | при каких отрицательных жизнях остаётся «месиво» |
| `minpain` | 0..999 | — | нижний порог боли |
| `sprite` | имя 1..4 символа | — | набор спрайтов в WAD |
| `frames` | 0..58 | из состояний | сколько кадров грузить (два ракурса на кадр) |
| `renderstyle` | `normal`, `invisible`, `fuzz` | `normal` | как рисовать |
| `translation` | 0..255 | 0 | цвет палитры, в который перекрашивается диапазон `0x70..0x7F` |

Значения по умолчанию — «как было у встроенного типа», поэтому мод может
указать одно поле и не повторять остальные.

### Спец-спрайты: ничего не рисовать

`sprite none`, `sprite NULL`, `sprite "----"`, `sprite TNT1` (и `TNT2`) —
синонимы. Актёр существует, сталкивается, получает урон и ходит, но на экране
его нет. Это то же, что `TNT1` в ZDoom, и старый маркер `----` из Doom.

Так делают невидимого монстра, триггер-помощника или «спектра» без картинки.
Если нужен именно полупрозрачный монстр, это `renderstyle fuzz`, а не спец-спрайт.

### RenderStyle

| Значение | Что делает |
|---|---|
| `normal` | как обычно |
| `invisible` | не рисуется вообще (то же, что спец-спрайт, но без смены имени) |
| `fuzz` | «призрак»: спрайт рисуется через пиксель (шахматка), силуэт читается |

`add`, `subtract`, `translucent`, `stencil`, `shadow` из ZDoom **не
поддерживаются** и дают ошибку `E106`. Это не лень: 8-битный палитровый
рендерер не умеет аддитивного смешивания, а честная реализация потребовала бы
таблиц на 256×256 на каждый стиль. `fuzz` сделан стипплингом — так же, как это
делал сам Doom, и он детерминирован.

### Translation

`translation 0xD0` перекрашивает пиксели спрайта из диапазона `0x70..0x7F` в
указанный цвет палитры. Это ровно тот механизм, которым в оригинале красились
игроки и труп игрока (`ManColor = 0xD0`) — то есть «трансляция» в терминах
Doom, только одной таблицей, а не массивом на 256 записей.

Полноценные таблицы трансляции (`Translation "0:255=..."` в ZDoom) — в
[плане работ](ROADMAP.md).

## Состояния

Девять состояний — это состояния `monster.c`, и их порядок совпадает с
нумерацией в сохранении, поэтому старые сейвы читаются как раньше.

| Метка | Когда |
|---|---|
| `spawn` | стоит без цели |
| `see` | увидел игрока, идёт |
| `pain` | получил урон |
| `wait` | ждёт |
| `melee` | атака вблизи |
| `death` | умирает |
| `slop` | разлетается на куски |
| `dead` | труп |
| `mess` | лужа |
| `missile` | дальняя атака (у кого есть; иначе берётся `melee`) |

Кадры — буквы `A`..`Z`, плюс `[`, `\`, `]` (ими нарисован огонь архивила).
Буква означает кадр спрайта, два ракурса берутся из WAD автоматически.

Длительность: `IMP2 AB 4` — каждая буква держится 4 тика. Внутри это
разворачивается в `AAAABBBB`, потому что движок листает по кадру за тик; так
`monster.c` не пришлось учить новому понятию.

```
death:
    IIIJJJ 5        // шесть кадров по пять тиков
    K 10            // один кадр десять тиков
```

## Ошибки

Каждая ошибка — строка `файл:строка: код: сообщение`. Игра пишет их в лог и
продолжает: битое поле означает «оставить как у встроенного типа», а не падение.

| Код | Что |
|---|---|
| `E101` | неизвестное свойство |
| `E102` | неизвестное состояние |
| `E103` | неверное значение (диапазон, тип, длительность) |
| `E104` | синтаксис: нет `{`, `}`, `:`, лишний символ, конец файла |
| `E105` | не поддерживается: наследование `actor X : Y`, `goto`, `loop`, `stop` |
| `E106` | неизвестный слот звука или renderstyle |
| `E107` | у актёра нет спрайта (внутренняя проверка встроенных данных) |
| `E108` | неизвестное имя актёра — новых типов пока нет |
| `E109` | буква кадра вне `A..Z`, `[`, `\`, `]` |
| `E110` | файл не читается |
| `W201` | предупреждение: пустое состояние без `none` |

## Чего пока нет

- **Новых типов.** Имя должно совпадать со встроенным (`Imp`, `Demon`, ...).
  Тип — это индекс в таблицах, и он же лежит в сохранении байтом. Добавление
  типов — следующий этап, см. [ROADMAP.md](ROADMAP.md).
- **Наследования.** `actor X : Imp` отвергается с `E105`, чтобы не создавать
  впечатление, что оно работает.
- **Действий и переходов.** `A_Chase`, `goto`, `loop` — следующие этапы.
- **Предметов и оружия.** Пока только монстры.

## Проверка

```
dptdoom2d.exe --actorcheck
```

Проверяет две вещи:

1. Встроенные данные совпадают с таблицами `monster.c` (эталон заморожен в
   `Game/ActorReference.cs`). Опечатка в `health` кибердемона — падение проверки,
   а не молчаливые 5000 жизней.
2. Парсер правильно отвергает битые файлы: для каждого кода ошибки есть
   намеренно сломанный сниппет.

`--actorcheck` проверяет **встроенные** данные. Если установлен мод, он честно
покажет расхождение — это диагностика, а не ошибка мода.

## Для агентов

Правила, по которым можно писать моды и не угадывать:

1. **Только то, что в этом файле.** Нет свойства — значит его нет. Не переносить
   сюда имена из ZDoom «по аналогии»: `Scale`, `Mass`, `Speed` не существуют.
2. **Один файл — один смысл.** Мод кладёт `actors.txt` в PK3 рядом с WAD'ами;
   собирать `--modbuild out.pk3 <dir>`.
3. **Проверять после каждой правки.** `--actorcheck` для встроенных данных,
   запуск игры для мода; ошибки читать как `файл:строка: код`.
4. **Не трогать C# ради мода.** Если чего-то не хватает — это пункт плана, а не
   повод править движок.
5. **Детерминизм.** Случайность только через `Glob.Rand`; в языке её пока нет
   вовсе, и это правильно: мод не должен уметь рассинхронить сеть.
6. **Никаких новых форматов.** WAD, карты, сохранения (`ver=3`) читаются как
   есть.

Список соответствий Doom II → этот язык — в [ROADMAP.md](ROADMAP.md), пункт 1.
