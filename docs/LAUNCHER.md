# Лаунчер

Интерфейс лаунчера — **настоящий HTML/CSS/JS**, который рисует `WebBrowser`
(MSHTML). Тот же подход, что в DPT.DOOM: никакой лишней зависимости (MSHTML есть
в каждой поддерживаемой Windows), а разметка живёт в файлах, которые можно
править без пересборки логики.

```
DPTDOOM2D.Launcher/
├─ LauncherForm.cs        окно, мост, команды
├─ LauncherSettings.cs    состояние и формат обмена с страницей
└─ Assets/
   ├─ ui.html             разметка
   ├─ theme.css           тема (тёмная и светлая)
   └─ app.js              вся логика страницы
```

Ассеты встроены в exe как `EmbeddedResource`; при старте они склеиваются в один
файл `Storage/webview/launcher.html` и открываются как локальный файл.

## Почему файл, а не `DocumentText`

Документ, присвоенный через `DocumentText`, живёт по адресу `about:blank`, и
MSHTML не на всех версиях Windows отдаёт такому origin хост-объект. Файл в зоне
Local Machine отдаёт всегда. Поэтому страница пишется на диск.

## Мост

COM не используется (`ObjectForScripting` требует MSHTML новее, чем есть на XP).
Вместо него — навигация:

```
страница → хост : сохранить payload, перейти на dptdoom2d://<verb>
                  хост отменяет переход и забирает payload обратно
хост → страница : dptReceive(verb, payload)
```

`dptdoom2d://` — приватная схема, перехода по ней не происходит никогда.

Важная деталь: MSHTML **приводит authority часть URI к нижнему регистру**, так
что `dptdoom2d://masterSave` приходит как `mastersave`. Разбор команд поэтому
регистронезависимый; на регистрозависимом сравнении молча не работали
«сохранить мастера», «обновить список» и «открыть лог».

## Команды

| От страницы | Что делает |
|---|---|
| `ready` | отдать тему, состояние, описание игры, статус |
| `preview` | пересчитать командную строку |
| `pack` | выбран другой пак карт — перечитать список уровней |
| `browse` | диалог выбора `dptdoom2d.exe` |
| `launch` | запустить игру |
| `mastersave` | запомнить адрес мастера |
| `masterrefresh` | запросить каталог сессий |
| `themesave` | запомнить тему |
| `openlog` | открыть папку с логами |

| К странице | Что несёт |
|---|---|
| `state` | состояние (поля через `\n`, порядок в `LauncherSettings.Encode`) |
| `game` | имя exe, папка данных, паки карт, число уровней, моды |
| `servers` | по строке на сессию: имя, карта, номер, игроки, адрес, порт, релей, id |
| `status` | текст и флаг ошибки через `\n` |
| `running` | `1`, пока игра запущена |
| `hasLog` | `1`, если папка логов уже существует |
| `storage` | где лаунчер и игра хранят файлы |
| `fatal` | текст ошибки лаунчера |

## Режимы

| Режим | Командная строка |
|---|---|
| Одиночная | `-warp N` |
| Хост · кооп | `-net host -port P -map N [-password X] [-master M -relay]` |
| Хост · DM | то же + `-deathmatch` |
| Подключиться | `-net join -address A -port P` или `-master M -relay-session ID` |

Плюс всегда: `-scale`, `-stretch`, `-fullscr`, `-map-pack`, `-file` для каждого
включённого мода.

## Раскладка управления

Поле «Раскладка управления» — это шаблон клавиш (см. [CONTROLS.md](CONTROLS.md)):

| Значение | Командная строка |
|---|---|
| «как в игре — свои привязки» | — (ключи не трогаются) |
| Шаблон 1 — стрелки + Z/X | `-layout 1` |
| Шаблон 2 — numpad (1996) | `-layout 2` |

Пустое значение по умолчанию: привязки, сделанные в оверлее (`F2` → **Keys**),
переживают запуск. Тот же шаблон, что и в сохранённых привязках, их сохраняет;
другой — сбрасывает (см. [CONTROLS.md](CONTROLS.md)).

## Моды

Список берётся из `Data/Mods` рядом с игрой: `.wad`, `.pk3`, `.zip`. Включённые
передаются в порядке отметки, так что патч, положенный ниже мода, его
перекрывает. Подробности — в [MODS.md](MODS.md).

## Сеть

Раздел «Серверы» запрашивает каталог у мастера (`MasterClient.List`), показывает
имя, карту и число игроков, и подставляет выбранную сессию в режим
«Подключиться»: адрес напрямую либо 32-символьный id через релей.

## Где что лежит

| Что | Где |
|---|---|
| настройки лаунчера | `launcher.cfg` рядом с лаунчером |
| страница лаунчера | `Storage/webview/launcher.html` |
| логи игры | `Storage/Logs/log_<дата>_<время>.log` |
| скриншоты | `Data/Screenshots/` |
