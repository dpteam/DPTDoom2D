# Сеть

## Модель: lockstep

Обе машины считают **один и тот же мир**. По проводу идёт только ввод, а не
состояние: четыре байта на игрока за тик. Мир не передаётся вообще, поэтому
трафик не зависит от количества монстров и размера карты.

Чтобы это работало, обе стороны должны получать одинаковый результат из
одинакового ввода. Для этого:

1. **Своё зерно ГПСЧ.** Хост выбирает seed, гость получает его в handshake.
   Генератор — LCG с константами MSVC `rand()`, а не `System.Random`, чья
   последовательность не гарантирована между рантаймами.
2. **Один порядок вызовов.** Тик всегда идёт в одном порядке (`Game.Act`), без
   ветвлений по времени кадра.
3. **Никакой паузы.** В сети меню недоступно: остановка одной машины — это
   десинк по определению.

## Протокол (версия 1)

Один TCP-сокет на всё. Кадр:

```
"D2" | type u8 | length u16 | payload
```

| type | кто | payload |
|---|---|---|
| 1 Hello | гость → хост | версия u16, пароль (32 байта ASCII) |
| 2 Welcome | хост → гость | версия u16, player u8, seed u32, map u8, dm u8, delay u8, тег |
| 3 Refuse | хост → гость | код u8 |
| 4 Tic | оба | тик u16 + ввод u16 (или тик u16 + чексумма u32) |
| 5 Chat | оба | UTF-8 |
| 6 Bye | оба | код u8 |
| 7 Ping / 8 Pong | оба | счётчик u32 |

Коды отказа: 1 версия, 2 мест нет, 3 пароль, 4 бан, 5 занято, 6 данные.

**Ввод** — битовая маска из девяти клавиш Doom2D (влево/вправо/вверх/вниз/
огонь/прыжок/использовать/оружие±), плюс запас под меню и чат.

## Порядок тика в сети

```
1. Сохранить локальное состояние клавиш
2. Отправить свой ввод для тика N
3. Ждать ввод пира для тика N     ← единственное место, где игра ждёт
4. Симулировать тик N (свой игрок + игрок пира)
5. Отправить чексумму мира для тика N
6. Сравнить чексумму с пиром для тика N-4
```

Сравнение идёт **на четыре тика позже** текущего: ответ пира на только что
отправленную сумму физически не может прийти, и сравнение «в лоб» давало бы
десинк на каждом тике из-за задержки.

**Чексумма** — FNV-1a по позициям и состояниям обоих игроков, всех живых
монстров и состоянию ГПСЧ. Десинк ловится за несколько тиков и печатается
номером тика и обоими значениями.

## Подмена ввода

Игровой код читает `keys[]` — как в 1996 году. Для второго игрока по сети
`Kbd.ApplyRemote` временно подменяет эту таблицу вводом пира и возвращает
локальный после `Player.Act`. Ни одна строка `player.c` не знает о сети.

## Хостинг

### Напрямую

```powershell
dptdoom2d.exe -net host -port 5041 -map 1
dptdoom2d.exe -net join -address 192.168.1.10 -port 5041
```

Хост слушает TCP-порт и ждёт одного гостя. Подходит для LAN или для машины с
проброшенным портом.

### Через мастер и релей

```powershell
dptdoom2d-master.exe --port 25145 --relay-port 25146

dptdoom2d.exe -net host -master 1.2.3.4:25145 -relay
dptdoom2d.exe -net join -master 1.2.3.4:25145 -relay-session <id>
```

Порядок:

1. Хост регистрируется на мастере и получает lease (аренду) на 60 секунд,
   которую продлевает heartbeat'ом.
2. Хост открывает **host-конец** релея и ждёт там.
3. Мастер печатает 32-символьный id сессии; его передают гостю любым способом.
4. Гость открывает **guest-конец** релея по id.
5. Релей соединяет два потока и больше в них не заглядывает.

Релей — это **тупой копировщик байт**: мастер не симулирует игру и не видит
ввод. Поэтому сессия через релей байт-в-байт та же, что напрямую, и десинка
«из-за релея» быть не может.

Проброс портов не нужен: обе машины подключаются наружу. UPnP тоже не нужен.

## Порты

Номера специально **не совпадают с DPT.DOOM** (там 25135 / 25136 / 5029), чтобы
оба проекта могли работать на одной машине и проброс на роутере указывал на
нужный.

| Что | Порт | Нужен снаружи |
|---|---|---|
| каталог мастера | **25145/tcp** | да, всегда |
| релей | **25146/tcp** | да, если играете через NAT |
| прямая игра (хост) | **5041/tcp** | только без релея |

### Брандмауэр

```powershell
./DPTDOOM2D/tools/firewall.ps1           # добавить правила (UAC)
./DPTDOOM2D/tools/firewall.ps1 -Status   # посмотреть, без прав
./DPTDOOM2D/tools/firewall.ps1 -Remove   # убрать
```

Скрипт создаёт три входящих правила с префиксом `DPT.DOOM 2D`, предварительно
удаляя одноимённые — иначе повторный запуск плодит дубликаты.

### Проброс на роутере

Проброс делает роутер, а не скрипт. Снаружи достаточно:

```
25145/tcp  -> компьютер с мастером
25146/tcp  -> компьютер с мастером
```

Игровой порт пробрасывать не нужно: при игре через релей обе машины подключаются
наружу, и мастер их соединяет.

### Запуск мастера для внешнего доступа

По умолчанию мастер слушает `127.0.0.1` — это безопасно, но снаружи недоступно.
Скрипт поднимает его на `0.0.0.0` с нужными портами:

```powershell
./DPTDOOM2D/tools/run-master.ps1            # в этом окне
./DPTDOOM2D/tools/run-master.ps1 -Firewall  # сначала правила (UAC)
```

Проверить снаружи:

```powershell
dptdoom2d.exe -net host -master play.dartpower.xyz:25145 -relay
dptdoom2d.exe -net join -master play.dartpower.xyz:25145 -relay-session <id>
```

В лаунчере адрес мастера по умолчанию — `play.dartpower.xyz:25145`, так что
достаточно нажать «Обновить список».

## Мастер-сервер

`dptdoom2d-master.exe` — отдельная программа, протокол общий с игрой
(`DPTDOOM2D.Shared`).

| Что | По умолчанию |
|---|---|
| порт каталога | 25145 |
| порт релея | 25146 |
| аренда сессии | 60 с, heartbeat раз в 30 с |
| сессий на релее | 8 |
| гостей на сессию | 3 |
| скорость на сессию | 64 КБ/с |
| простой | 120 с |

Каталог — это одна TCP-сессия «запрос-ответ»: список сессий, регистрация,
heartbeat, снятие, открытие релея. Формат записан в `MasterProtocol.cs`, чтобы
клиент, сервер и тесты не могли разойтись в трактовке полей.

## Ограничения

- **Два игрока.** Doom2D — игра на двоих; протокол это отражает.
- **TCP, не UDP.** Ввод маленький и должен доходить, а не «по возможности»;
  lockstep всё равно ждёт пира, так что выигрыша от UDP нет.
- **Задержка = RTT.** Ввод применяется сразу, поэтому задержка ощущается как
  «второй игрок двигается с запозданием», а не как рывки.
- **Нет докачки мира.** Обе стороны должны иметь одинаковый `doom2d.wad`;
  расхождение ловится чексуммой в первом же тике.
